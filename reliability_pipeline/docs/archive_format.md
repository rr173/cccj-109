# tele_samples 折线压缩归档（TPLA）：格式、算法与误差承诺

`telemetry.arch*` 子系统把 DuckDB 中**已接纳**的 `tele_samples` 压缩成
**带绝对误差上限的折线归档**（TPLA，Telemetry PolyLine Archive），供
离线工作站使用。它只做测量值的压缩归档与解码，不改遥测入库过程，
不推导故障结局、不计算生存曲线。

命令行入口：`python3 -m telemetry.archcli`（见文末）；一条命令演示：

```bash
./run_archive_demo.sh
```

## 1. 目标与保证

- **输入选择**：调用者指定 `device_id`、`channel`、纳秒时间范围
  `[t_start, t_end)` 与容差 `epsilon`（该通道**最终物理单位**下的绝对
  误差上限，必须是正的有限值；`0`/负数/NaN/Inf 一律拒绝）。
- **误差承诺**：对归档中的**每一个**原采样点，
  `|解码值 − 原物理值| ≤ epsilon`——含每段首尾与任何尖峰。承诺逐点
  成立，不凭「两个端点接近」推断中间点（见 §4 的判据与 §5 的论证）。
- **时刻与来源**：逐点保留**精确时刻**（i64 纳秒，不转浮点）与
  **原测量定位键** `(file_id, frame_offset, ordinal)`；解码结果还带
  单位与所属线段号，任何读数都能回溯到来源帧与通道声明。
- **解码自足**：解码器只依赖归档文件本身，不回查数据库。

## 2. 分组与排序

组 = `(boot_seq, layout_id, unit)`：**启动周期、布局或单位不同的读数
绝不共用一段折线**。设备与通道由调用者固定，不参与分组键。

组内排序：`ts_ns, file_id, frame_offset, ordinal`（时刻相同再按来源
文件、帧位置、通道序位）。同一时刻的多个样本是**不同采样点**：不合并、
不去重，全部进归档；若同一时刻的值不能由同一个近似值满足容差
（冲突的重复时间），**必须切段**（§4）。

## 3. 线段模型与解码公式

每段保存 24 字节模型参数 `(t0: i64, y0: f64, slope: f64)`：

```
dec(t) = y0 + slope * float(t - t0)
```

- 解码值**只能**由该段保存的模型参数与样本时刻算出；归档中不存在
  任何逐点物理值、残差数组或等价索引；
- `t - t0` 先在整数域相减（Python 任意精度 int / 文件内 i64），
  **再**转 f64 参与乘加：巨大 Unix 纳秒基数（如 1.7e18，远超 2^53）
  下相隔 1 纳秒的时刻差值不丢失；绝对时刻从不先转浮点；
- 只有同一时刻的段（重复时刻点列）`slope` 记 0.0，解码恒为 `y0`。

## 4. 分段算法与切段判据

在线算法，每组 O(1) 状态，不追求全局最少线段：

1. 段以点 `(t0, v0)` 开头，`y0 = v0`（首点解码恒等于原值）；
2. 段内第二个**不同时刻**的点确定 `slope = (v − v0)/float(t − t0)`
   （f64），此后模型固定；候选 slope 非有限按试算失败处理；
3. **每个新点都用 §3 公式试算解码值**（与解码器逐指令相同的浮点
   运算序列），`|dec(t) − v| ≤ eps` 则接纳，否则当前段收尾、新点
   开启新段；
4. 同一时刻的重复点：解码恒为 `y0`，`|y0 − v| > eps` 即切段
   （冲突重复时刻各自成段）；相容重复点可共存一段；
5. 组结束或块写满时收尾当前段（块写满只切**部件**，段可跨块延续，
   见 §6）。

由此，长的精确直线（含不等间隔采样、1ns 间隔）自然压成一段；锯齿、
尖峰等局部剧烈变化只在局部切段。尖峰点要么落在某段内容差达标，
要么自己开段——**任何峰值都与普通点受同一约束**。

## 5. 误差承诺成立的理由

- 段的模型在**第二个不同时刻点之后固定**，此后每个点的接纳判据就是
  「最终存储模型在该点时刻的解码值与原值之差 ≤ eps」，且试算用的
  浮点运算序列与解码器**逐指令一致**（先整数差、再 `float()`、再
  乘加，IEEE 754 双精度，结果可复现）。因此被接纳的每个点相对
  **最终落盘的模型**误差 ≤ eps 在写入时已逐点验证；
- 模型固定前接纳的点全部共享段首时刻 `t0`，其解码值恒为
  `y0 + slope*float(0) = y0`（`slope` 有限 ⇒ `slope*0.0 = 0.0` 精确），
  与固定后采用什么 slope 无关；
- 段首点误差为 0（`dec(t0) = y0 = v0`）；单点段退化为常数模型，
  同样精确；
- 切段瞬间被吐出的段，其全部点都已按上述判据验证——承诺不依赖
  任何「端点接近则中间安全」的间接推断；
- **独立核验**（`telemetry.archverify` / `verify` 子命令）不用压缩器
  的内部统计：它按 §7 格式重新解析归档文件，用单独的简单解码器
  逐点重算 f64 解码值并与 DuckDB 原值比对（要求 `≤ eps`），另用
  精确分数算术（模型参数与时刻都是精确值）复核每点误差不超过
  `eps + 浮点求值余量`（余量按解码公式舍入上界逐点给出），同时
  核对逐点 `(ts_ns, file_id, frame_offset, ordinal)` 序列与库中查询
  结果逐项一致（不漏点、不多点、次序与定位键不变）。

## 6. 分块与时间索引

归档按**点数千位级**切成独立数据块（默认目标 4096 点/块，构建参数
`--block-points` 可调；组边界必然切块的边界）：

- 块是**自包含解码单元**：块内每个线段部件都带完整模型参数；
- 段可跨块延续：同一 `seg_seq` 在每个涉及块里各存一份参数（计入
  参数区字节）。极端情形（整块都是同一时刻的重复点、段 slope 尚未
  确定）下，先写的块为该段存占位 slope 0.0——该块内点全部同时刻，
  解码恒为 `y0`，自洽；后续块再续记确定后的参数；
- 块索引记录每块 `(group_id, t_min, t_max, 文件偏移, 长度)`。范围
  查询 `[a, b)` 只读取 `t_min < b 且 t_max ≥ a` 的块，并**报告实际
  读取块数**；相邻块边界上的重复时刻会让两个块都被选中，各块再
  按点过滤——点集是划分的，不漏不重；
- 时刻/定位键随点顺序落盘（每块缓冲 ≤ `block_points` 条），物理值
  的在途状态只有当前段模型与当前点（常数上界）。

## 7. 文件格式（多字节一律小端）

```
文件头 64B   │ magic "TPLA" u32, version u16=1, flags u16,
             │ device_id i32, channel i32, epsilon f64,
             │ t_start i64, t_end i64, group_count u32, block_count u32,
             │ created_unix i64, header_crc u32, 保留 4B
             │ （CRC32 覆盖前 56 字节）
数据块 × N   │ 块头 40B：magic "BLK1" u32, block_len u32, group_id u32,
             │   point_count u32, part_count u32, flags u32,
             │   t_min i64, t_max i64
             │ 部件 × P，各 40B：seg_seq u32, start_point u32,
             │   point_count u32, reserved u32,
             │   t0 i64, y0 f64, slope f64   ← 后 24B 为模型参数区
             │ 逐点记录 × M，各 22B：ts_ns i64, file_id i32,
             │   frame_offset i64, ordinal u16   ← 不含物理值
             │ block_crc u32（覆盖块头+部件+点记录）
块索引       │ magic "IDX1" u32, count u32，随后 count × 40B：
             │   group_id u32, t_min i64, t_max i64,
             │   file_off u64, block_len u32（含对齐填充）
             │ index_crc u32
组目录       │ magic "GRP1" u32, count u32，随后每组：
             │   group_id u32, boot_seq i64, layout_id i32,
             │   unit_len u16, flags u16, unit UTF-8 字节（≤255B），
             │   point_count u64, seg_count u64, param_bytes u64,
             │   block_start u32, block_count u32
             │ dir_crc u32
文件尾 36B   │ index_off u64, index_len u32, dir_off u64, dir_len u32,
             │ footer_crc u32（覆盖前 24 字节）, tail_magic 8B
```

部件按 `start_point` 升序无缝覆盖块内全部点（读取时校验）。索引与
目录集中在文件尾：构建顺序写块，收尾一次性写索引/目录/文件尾并
回填文件头计数。

## 8. 截断与损坏检测

- 打开时：文件头魔数/版本/CRC、文件尾魔数/CRC、索引与目录各自
  CRC、索引/目录位置合法性、计数与文件头一致性——任一不符抛
  `ArchiveError`；
- 每读一块：块魔数、声明长度与实际可读字节、块头与索引一致性、
  内容长度自洽、部件无缝覆盖、整块 CRC32——不符抛 `ArchiveError`
  并指明块号；
- **绝不输出被称为完整的部分结果**：完整解码遇到坏块直接失败；
  范围查询只承诺所读块，若涉及坏块同样失败（不触碰坏块的窄查询
  不受影响，它本就不声称覆盖全文件）。

## 9. 流式构建与内存上界

- 样本用**键集分页**逐批取出
  （`WHERE (ts_ns, file_id, frame_offset, ordinal) > (上批末行键)
  ORDER BY … LIMIT B`），Python 侧在途样本 ≤ B 行，不把整组原值
  载入内存；
- 分段器每组 O(1)：段首 `(t0, v0)`、`slope`、段内点数——一条多长
  的精确直线也只缓存模型参数，**绝不缓存它的全部原值**；
- 逐点（时刻/定位键）缓冲 ≤ 一个块即落盘；块索引与组目录随块/组
  各增一条定长记录，随文件结构线性增长，与原值总量无关；
- 物理值在途上界 = 当前段模型（24B）+ 当前点（常数）。

## 10. 摘要口径

`summary` 列出各组点数、线段数、参数区字节（24B × 部件数）与块数，
并给出全文件口径：

- **物理值参数区** vs **原样存值基线**（8B/点）：只有这个比值 < 1
  才算压掉了物理值；
- **逐点时刻+定位键**（22B/点）是精确时刻与来源回溯的必需成本，
  **不计入压缩收益**，单独列示；块结构开销与头/索引/目录/尾同样
  单独列示。

病态数据（每个点都自成一段）下参数区会大于原样存值，摘要如实显示
比值 > 1，不粉饰。

## 11. 命令行

```bash
# 构建（设备/通道/纳秒范围/容差）
python3 -m telemetry.archcli build --db outputs/telemetry.duckdb \
    --device 7 --channel 0 --start-ns 1700000000000000000 \
    --end-ns 1700000001000000000 --epsilon 0.05 --out out.tpla

python3 -m telemetry.archcli summary --file out.tpla     # 摘要
python3 -m telemetry.archcli decode  --file out.tpla --limit 20
python3 -m telemetry.archcli query   --file out.tpla \
    --start-ns 1700000000400000000 --end-ns 1700000000500000000
python3 -m telemetry.archcli verify  --file out.tpla \
    --db outputs/telemetry.duckdb                        # 独立核验
python3 -m telemetry.archcli demo    --workdir outputs/archive_demo
```

`verify` 退出码：0 通过；1 有违规；4 文件损坏/截断。

## 12. 局限

- 分段是贪心在线算法，不保证全局最少线段；模型由段内前两个不同
  时刻点确定，对「噪声小于容差的近似直线」可能切得比理论最优碎；
- 单点段/两点段的参数（24B）大于原值（8B），极端抖动数据会负压缩
  （摘要如实反映）；
- 容差小于 f64 回代误差（约 1e-16 相对量级）时，长段会退化为大量
  短段——误差承诺仍然成立，只是压缩率下降。
